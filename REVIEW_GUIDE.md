# REVIEW_GUIDE.md — плейбук ревьюера

Практическое руководство для того, кто ревьюит этот автобатлер (роль Qoder).
Дополняет, не дублирует:
- `AGENTS.md` — технические правила и инварианты репозитория;
- `WORKFLOW.md` — разделение ролей OpenCode/Qoder и экономия кредитов;
- `REVIEW_FIXES.md` — история конкретных багов (Было → Стало → Почему → Где → Тест).

Дата актуализации: 2026-11-10. Сюита на этот момент: **315 passed**.

---

## 0. Золотое правило

**Не верь отчёту OpenCode — проверяй эмпирически.** «Тесты зелёные» ≠ «игра не
падает». Сюита ловит логику ядра/движка, но **не ловит краши UI-рендера**: игра
может закрываться прямо в бою при 315 passed. Всегда прогоняй реальный UI-поток
(headless) и смотри картинку/трейсбек, а не только `pytest`.

Отчёт OpenCode — это заявление о намерении, а не доказательство результата.
Перед вердиктом: запусти команды ниже, открой PNG, прочитай diff целиком.

## 1. Быстрый старт (команды)

Все команды из корня репозитория. Windows cp1251 → всюду `PYTHONIOENCODING=utf-8`.

```bash
# Сюита. ТОЛЬКО tests/, не голый pytest (в _scratch/ старые test_*.py
# открывают pygame на импорте → коллекция зависает).
PYTHONIOENCODING=utf-8 python -m pytest tests/ -q

# Headless-рендер драфта (смотреть PNG, а не «на глаз»):
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy PYTHONPATH=. \
  python _scratch/render_draft_layout.py 1200 800   # → _scratch/layout_1200x800.png
# минимум два разрешения: 1200×800 и 1920×1080.

# Сквозной repro реального матча со скриптованными событиями pygame:
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy PYTHONIOENCODING=utf-8 PYTHONPATH=. \
  python _scratch/repro_upgrade_crash.py 1          # [seed]

# Стресс боевого рендера: все расы × звёзды 1/2/3 × предметы × 3 сида:
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy PYTHONIOENCODING=utf-8 PYTHONPATH=. \
  python _scratch/stress_battle_ui.py               # 138 боёв, ловит краши рендера

# Баланс-харнесы (детерминированный хеш, 100 семян):
PYTHONIOENCODING=utf-8 python _scratch/mix_balance_report.py   # микс 40-60% + контры
PYTHONIOENCODING=utf-8 python _scratch/balance_report.py       # моно-гейты
```

`_scratch/` в `.gitignore` — харнесы не коммитятся, но должны оставаться
рабочими. Если харнес сломан после правок — это сигнал, что контракт поехал.

## 2. Инварианты — единые источники истины

Проверяй при любом ревью core/battle/ui:

- **Имена юнитов** `base` / `base★2` / `base★3` парсятся ТОЛЬКО через
  `game/core/unit_name.py` (`base_name`, `star_level`, `star_multiplier`).
  Запрещено `split("★")[1][1:]` — срез `[1:]` от цифры даёт `""` → `int("")` падает.
- **Боевая команда** собирается ТОЛЬКО `game/core/team.py:build_combat_team`
  (звёзды + предметы + расы + синергии + пассивки). `item_bonuses` применяются
  там один раз; в engine их не пробрасывать и не применять повторно.
- **`BENCH_MAX`** — из `game/core/player.py` (=9). Учёт пула — `shop.POOL_COST_BY_STAR`.
- **PvP-урон** — `economy.pvp_round_damage(round, winner_survivors)` (от выживших
  ПОБЕДИТЕЛЯ, не проигравшего).
- **Уровень магазина = уровень игрока** (апгрейд магазина отключён).
- **Время** — 60 тиков = 1 сек (`engine.TICKS_PER_SECOND`); cooldown/duration
  нормализуются секунды→тики в `add_team`.
- **Слои не смешивать**: `game/core` (правила), `game/battle` (детерминированный
  тик-симулятор, без pygame), `ui` (рендер/ввод, без игровой логики), `data` (JSON).
- **RNG** только seeded (`self.rng`). Никаких авто-винов: evasion ≤40%,
  revive ≤2, lifesteal ≤30%.

## 3. Чек-лист ревью по слоям

### game/core
- [ ] Пул: стоимость копий по звезде верна, фантомные `base★2` не плодятся.
- [ ] Слияние: забирает копии и с доски, и из резерва; `len(reserve) <= BENCH_MAX`.
- [ ] `Player.place`: не падает на ★2/★3 и на полной доске, юнит не теряется.
- [ ] Экономика: стрики обновляются, золото за реролл списывается ПОСЛЕ попытки.
- [ ] Бонусы предметов накапливаются одним хелпером (`accumulate_item_bonuses`),
  `speed_bonus_pct` доезжает до боя.

### game/battle
- [ ] Детерминизм: один seed → один результат; никаких `random` вне `self.rng`.
- [ ] Расовые механики (evasion/lifesteal/berserker/revive/unity) применяются
  через `build_combat_team` → `add_team` → атрибуты Unit, не дублируются.
- [ ] Новые типы событий (`miss`/`lifesteal`/`revive`) имеют обработчик в UI
  (иначе краш или тихая потеря визуала).

### ui (самая частая зона крашей)
- [ ] Геометрия отрисовки и хит-ректы клика/драга считаются ОДНИМИ формулами
  (иначе хит-ректы расходятся с картинкой).
- [ ] KWARG-и рендер-хелперов совпадают с сигнатурой (`draw_text_overlay`
  принимает `text_color=`, НЕ `color=`).
- [ ] Визуальные эффекты принимают и числа, и строковые метки
  (`DamageNumber`: строка = метка, число = урон).
- [ ] Пустая доска `[]` не сбрасывает золото/уровень/предметы.
- [ ] Бой берёт всю доску, не `board[:6]` (на уровнях 7+ юниты сверх 6 воюют).
- [ ] `shop.level` синхронизирован после `buy_xp`.
- [ ] Headless-рендер на 2+ разрешениях: ничего не налезает, не вылетает за экран.
- [ ] **Боевой рендер прогнан со всеми расами** (стресс-харнес), а не только
  `_draw_battle_scene` на одной картинке.

### data
- [ ] JSON валиден, ключи синергий/рас совпадают с тем, что читает код.
- [ ] Баланс-гейты пройдены (см. §5); desc не обещает механик, которых нет.

## 4. Каталог повторяющихся багов (паттерн → как ловить)

Накопленный опыт. При ревью сначала проверь эти паттерны — они возвращаются.

| Паттерн | Симптом | Как ловить |
|---|---|---|
| `color=` вместо `text_color=` в `draw_text_overlay` | краш на СТАРТЕ боя, когда у команды 2+ юнитов одной расы (бейдж) или орк под порогом HP («ЯРОСТЬ») | headless `_draw_battle_scene` с бейджем + берсерком; `repro_upgrade_crash.py` |
| `int(amount)` в `DamageNumber` на строке `"MISS"`/`"REVIVE"` | краш В ХОДЕ боя на первом уклонении эльфа / восстании нежити | `stress_battle_ui.py` (все расы); `_generate_battle_effects` с событиями miss/revive |
| `int(name.split("★")[1][1:])` | `ValueError` на любом ★2/★3 | grep по `split("★")`; тесты `TestStarHelpers` |
| Двойное применение `item_bonuses` | завышенные HP/урон юнитов с вещами | тест `TestItemBonusSingleSource`; сверка engine vs team |
| PvP-урон от выживших ПРОИГРАВШЕГО | бонус за выживших всегда 0 | `TestPvpDamage`; `economy.pvp_round_damage` |
| Пустая доска `[]` сбрасывает состояние | золото/уровень/вещи обнуляются | прогон драфта с пустой доской |
| `board[:6]` в бою | на уровнях 7+ юниты сверх 6 не воюют | грепнуть срез; тест на доску 7+ |
| Золото за реролл до попытки | золото теряется при ошибке ролла | `TestRollCost` |
| `shop.level` не синхронизирован после `buy_xp` | ролл по старым шансам до след. раунда | прогон buy_xp → roll |
| Плоский бафф орков вместо % | «Крик войны» даёт +30, а не +30% | `TestOrcPercentageBuff` |
| «Проклятие» суккуба лечит врага | дебафф работает как щит | `TestSuccubusCurseSemantics` |
| `damage_reduction_pct` нежити игнорируется | расовый бонус не работает | `TestUndeadDamageReduction` |

**Мета-урок:** краши UI-рендера не видят ни тесты движка, ни баланс-харнесы.
Обязателен headless-прогон реального боевого потока (`stress_battle_ui.py` +
`repro_upgrade_crash.py`), иначе «315 passed» может скрывать падающую игру.

## 5. Баланс-гейты и текущие цифры

Цель микс-харнеса: **каждая раса 40-60% overall** (100 семян, детерминированный
хеш). Моно-гейты: нежить vs поле ≤60%, демон t1-2 vs поле ≥40%, max overall ≤65%.

Текущие цифры (2026-11-10, `_scratch/mix_balance_report.py`):
- Человек 45.6% ✓ / Орк 60.0% ✓ (граница) / Демон 56.9% ✓ / Эльф 59.4% ✓ / Нежить 49.7% ✓.
- Контр-матрица (цель >55% контрящей расы): Elf→Undead 62% ✓, Elf→Demon 58% ✓,
  Demon→Elf 47% ✗, Elf→Orc 54% ✗. Два мягких контра оставлены как сигнал —
  overall не жертвовался. Это допустимый остаток, не баг.

Расовые идентичности (не «одинаковые математически»): эльф — уклонение,
орк — берсерк (чем меньше HP, тем сильнее), демон — вампиризм/DoT,
нежить — восстание, человек — единство (бонус за уникальные классы).
Подробности: `TASK_race_identities.md`, `data/units.json:races/race_synergies`.

При баланс-ревью: сначала прогони харнесы и сравни с гейтами, не правь JSON
«на глаз». Мягкие контры <55% — не блокер, если overall в коридоре.

## 6. Git-безопасность

- **Не коммитить без явной просьбы пользователя.**
- Перед любой git-операцией, способной потерять работу (`checkout --`,
  `reset --hard`, `restore`, `clean`): `git status`, затем stash/backup.
  Уничтожение working-tree необратимо.
- Не удалять `package.json` / `package-lock.json` (инструментарий OpenCode).
- Не коммитить секреты: конфиги OpenCode (`~/.config/opencode/`,
  `~/AppData/Roaming/opencode/`) содержат apiKey/password — они вне репозитория
  и `.opencode/` в `.gitignore`. Проверять содержимое подозрительных файлов.
- Дампы вывода тестов (`full_suite.txt`, `review_regressions.txt`) в `.gitignore`
  — не коммитить.
- Стиль коммитов: `type: краткое описание по-русски` (`fix:`, `balance:`,
  `feat:`, `docs:`).HEREDOC для сообщения.

## 7. Что возвращать OpenCode (формат вердикта)

Один сводный вердикт на milestone (экономия кредитов), а не десять мелких:
1. **Что проверено эмпирически** (команды + результат: N passed, рендеры, repro).
2. **Найденные баги** по схеме Было → Стало → Почему → Где (file:line) → Тест.
3. **Блокеры** (краши, нарушение инвариантов, баланс вне гейтов) — чинить до финала.
4. **Неблокеры** (мягкие контра, косметика) — можно отложить.
5. **Регрессии**: на каждый исправленный баг — тест в
   `tests/test_review_regressions.py`; сюита зелёная до и после.

После правок обновляй `REVIEW_FIXES.md` (и `PROJECT_STATE` / `MINI_STATE` при
смене состояния проекта). Номера строк смещаются — надёжнее искать по имени
функции/символа.
