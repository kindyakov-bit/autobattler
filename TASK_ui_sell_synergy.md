# TASK_ui_sell_synergy.md — продажа под бенчем + тултип бонусов синергий

Две UX-правки в фазе драфта (`ui/game_ui.py`, метод `_draw_interactive_draft` и его
обработчики событий). Игровую логику (экономика, пул, продажа) не менять — только
UI-расположение и отображение. Общение, надписи в UI и документация — на русском.

## Контекст: как устроено сейчас (якоря)

- **Корзина продажи уже есть**, но стоит справа и принимает только с бенча:
  - Константы `SELL_BIN_W/H/PAD` — `ui/game_ui.py:105-107`.
  - Отрисовка — `ui/game_ui.py:1604-1620`: `bin_x = self.width - SELL_BIN_W - SCREEN_MARGIN`,
    `bin_y = BENCH_Y0 + 30` (правый край экрана, на высоте заголовка бенча).
    Рект сохраняется в `self.sell_bin_rect`.
  - Продажа дропом с бенча — `ui/game_ui.py:2511-2524`: если юнит не размещён на поле
    и курсор в `sell_bin_rect` → `draft_phase.sell_unit(player, bench_idx)` +
    `player.gold += cost` (cost = цена базового юнита из `all_units`).
  - Драг с доски (`drag_board_idx`, обработчик с `ui/game_ui.py:2528`) продажу НЕ умеет:
    если клетка не найдена — юнит возвращается на исходную клетку.
  - Клавиша S (`ui/game_ui.py:2134-2143`) продаёт последнего юнита с бенча — не трогать.
- **Продажа в ядре** — `game/core/shop.py:121` `Shop.sell(player, idx, from_board=False)`:
  удаляет юнита, возвращает копию в пул (`POOL_COST_BY_STAR`), при `from_board=True`
  возвращает предметы юнита в `player.items`. Золото НЕ начисляет — это делает вызывающая
  сторона (базовая цена юнита). `DraftPhase.sell_unit` (`game/core/draft.py:27`)
  пробрасывает `from_board`.
- **Бенч** — отрисовка `ui/game_ui.py:1536-1553`. Геометрия панели:
  `x=10`, `y=BENCH_Y0 (268)`, `bench_panel_w = self.width // 3 - 40`,
  `bench_cell_w = max(50, (bench_panel_w - 2*BENCH_SIDE_PAD - (BENCH_COLS-1)*BENCH_CELL_MARGIN) // BENCH_COLS)`,
  `bench_panel_h = 40 + BENCH_ROWS*bench_cell_h + (BENCH_ROWS-1)*BENCH_CELL_MARGIN + 10`.
  Низ панели = `BENCH_Y0 + bench_panel_h` (для 1200×800 это 656).
  Кнопка «Начать раунд» — `pygame.Rect(self.width//2 - 100, self.height - 90, 200, 44)`
  (`ui/game_ui.py:1767`), подсказка управления — `self.height - 30` (`:1791`).
- **Панель синергий** — `ui/game_ui.py:1736-1759`: правая треть
  (`syn_x = self.width//3*2 + 10`), записи только при count ≥ 2, текст `"{name}: {count}"`
  шрифтом `font_tiny`, строки с шагом 20 от `BOARD_Y0 + 21`. Хит-ректы не сохраняются,
  ховера нет. Данные: `synergy_data` (классы: `thresholds=[2,4]`, `bonuses={"2": {...}, "4": {...}}`,
  `name` — русское имя) и `race_synergy_data` (расы: `thresholds=[2,4,6]`, вложенные
  `berserker`/`revive`). Оба словаря уже передаются в `_draw_interactive_draft`.
- **Тултип-хелпер** — `draw_tooltip(surf, x, y, text, font=None)` (`ui/sprites.py:317`):
  многострочный текст, сам клампит по границам экрана. Используется магазином
  (`ui/game_ui.py:1894`) и предметами (`:1940`). Рисовать тултипы в конце отрисовки,
  поверх всех панелей (паттерн `shop_hover_tooltip`, `:1802-1804`).

## Задача 1 — зона продажи под бенчем (слева внизу)

1. Перенести корзину из правого края в **горизонтальную полосу под панелью бенча**:
   - `x = 10` (левый край панели бенча), `y = BENCH_Y0 + bench_panel_h + 6`,
     `w = bench_panel_w`, `h = min(44, (self.height - 90) - y - 6)` (зазор до кнопки
     «Начать раунд»). Если при каком-то разрешении `h < 32` — не рисовать полосу
     (старое поведение продажи через S остаётся).
   - **Единый источник геометрии**: вычисление в одном маленьком методе
     (например `_sell_bin_rect(self) -> pygame.Rect`), который вызывают И отрисовка,
     И оба обработчика дропа. Требование AGENTS.md: геометрия отрисовки и хит-ректы
     считаются одинаково. `self.sell_bin_rect` можно по-прежнему сохранять при отрисовке, но
     обработчики должны получать рект тем же методом (не полагаться на устаревший
     рект с другого разрешения).
   - Старую корзину справа **удалить** (две корзины не оставлять). Константы
     `SELL_BIN_W/H/PAD` заменить/переиспользовать под новую полосу — без мёртвых
     констант.
2. Оформление: фон `(120, 60, 60)`, при наведении/перетаскивании над зоной —
   `(180, 80, 80)`, белая рамка, надпись по центру «Продать — перетащи юнита сюда»
   (`font_tiny`). Иконку корзины можно убрать (полоса низкая).
3. Принимать дроп **и с бенча, и с доски**:
   - С бенча — как сейчас: `draft_phase.sell_unit(player, bench_idx)`,
     `player.gold += cost` базового юнита, звук `gold`.
   - С доски — `draft_phase.sell_unit(player, idx, from_board=True)` (предметы
     вернутся в инвентарь сами), `player.gold += cost` базового юнита, звук `gold`.
     Индекс доски — это `self.drag_board_idx` (юнит уже изъят с доски в начале
     драга, `player.board.pop` на `:2417`): продавать нужно ПОСЛЕ того, как юнит
     возвращён в `player.board`, либо продавать напрямую из `drag_board_data`
     через `Shop.sell(from_board=True)` уже после возврата — выбрать один корректный
     путь и закрепить тестом. Главное: юнит не должен двоиться и не должен теряться,
     предметы не должны пропадать.
   - `ShopError` при продаже показывать через `self.draft_message = (str(e), pygame.time.get_ticks())`
     (паттерн магазина), а не глотать `except Exception: pass`.
4. Экономику не менять: возврат золота = базовая цена юнита (как в текущей корзине
   и клавише S), возврат копий в пул — внутри `Shop.sell`. Клавишу S и возврат юнита
   на исходную клетку при дропе мимо корзины не ломать.

## Задача 2 — тултип бонусов при наведении на синергию

1. В панели SYNERGIES (`ui/game_ui.py:1736-1759`) для каждой записи сохранять хит-рект:
   `syn_text.get_rect(topleft=(syn_x, y)).inflate(6, 4)`. Определять наведение курсора
   (`mx, my` уже есть в методе). Записи и фильтр count ≥ 2 не менять.
2. При наведении рисовать тултип **в конце** `_draw_interactive_draft` (поверх всех
   панелей, паттерн `shop_hover_tooltip`) через `draw_tooltip`:
   - Позиция: слева от панели (`x = syn_x - 280`, `y = y строки`); `draw_tooltip`
     сам клампит по экрану.
   - Содержимое (все цифры — из JSON, не хардкодить):
     ```
     Воин (-warrior-): 3 на доске
     2 (активно): +15% HP
     4 (следующий): +30% HP
     ```
     Для рас — то же самое по `race_synergy_data` (пороги 2/4/6). Активный порог —
     максимальный порог ≤ count; следующий — минимальный порог > count; остальные
     просто перечислить. Русское имя брать из `data[key]["name"]`.
3. **Единый форматтер бонусов** — один маленький хелпер в UI-слое
   (например `_format_synergy_bonus(bonus: dict) -> str`), общий для классов и рас.
   Карта подписок (ключ → текст):
   - `hp_bonus_pct` → «+N% HP»; `damage_bonus_pct` → «+N% урона»;
     `attack_speed_pct` → «+N% скорости атаки»; `crit_chance_bonus` → «+N% шанс крита»;
     `mana_per_kill` → «к/д −N сек за убийство»;
   - `evasion_pct` → «уклонение N%»; `lifesteal_pct` → «вампиризм N%»;
     `damage_reduction_pct` → «−N% получаемого урона»; `hp_regen_pct` → «реген N% HP»;
     `gold_bonus_pct` → «+N% золота»;
   - `unity_damage_pct` / `unity_hp_pct` → «единство: +N% урона / +N% HP за уникальный класс»;
   - `berserker` (dict) → «берсерк: +{damage_pct[-1]}% урона/скорости при HP≤{hp_thresholds[0]}%»;
   - `revive` (dict) → «восстание: {hp_pct}% HP, до {max_revives} раз»;
   - неизвестный ключ → «ключ: значение» (не падать).
   Несколько ключей в одном пороге соединять через «; ».
4. Тултип не должен ломать существующие тултипы магазина/предметов и не должен
   рисоваться, когда курсор вне записей.
